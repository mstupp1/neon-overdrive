# VECTOR generated hull study

The starter all-rounder retains its long pointed nose, small forward canards, swept rear wings, twin rear engines, cyan cockpit and electric cyan ship identity. Silver/gunmetal broad armor panels add illustrated depth. The selected set contains a directly overhead nose-up view, a shallow side elevation facing right, and a centered elevated rear pursuit view. The side and rear candidates were revised when initial generations retained too much of the overhead camera. Exact prompts, selected full-resolution masters, source/output hashes, references and measured mount pixels are mapped in `manifest.json`.

Created using built-in imagegen. The selected top revision moves the pulse cannons from the wingtips to the forward fuselage. Measured final cannon-tip positions drive bullet origins and muzzle flashes; engine anchors drive separate live flames. Upgraded volleys share the two physical cannons while keeping their stream counts, angles, speed, damage and cadence. Sprite banking, side-world rotation, free-flight heading and the pursuit camera are applied to the attachment points. The pursuit flight plane is inverted at each visible cannon tip, avoiding a mismatch between projected bullets and the hull cutout.

Runtime exports are 256×256 RGBA PNGs made with `tools/ship_assets.py`, preserving aspect ratio and genuine alpha. The renderer fits each view inside its logical hull footprint and caches the decoded/baked canvases. Cyan paint accents can be recolored while neutral metal remains shaded. Original procedural art remains available for loading or failed images; each camera can fall back independently. VECTOR established the workflow later extended to the [remaining fleet](../README.md); collision radius and input remain unchanged.

Review with `/tools/ship-art-preview.html`. The catalog includes measured muzzle guides, bank and paint controls, and native-size samples. The isolated live game supports top/side/pursuit, weapon levels, pixel look and a firing-registration check. Preview saves remain in memory.

Validation: 25 subsystem tests pass, including six new asset provenance, cannon geometry and fallback tests. The browser check verified 468 actual bullet spawn positions across three cameras, all eight pulse levels and three bank angles, with maximum error below 0.00001 logical pixels. All three PNGs passed RGBA, real transparency and clear-border validation. JavaScript syntax and diff whitespace checks pass. Both the new subject-art skill and updated background skill pass the skill validator using the system Python interpreter.

Visual review covered all three live cameras, normal and pixel look, stock and crimson recoloring, and the narrow portrait preview layout. The catalog and live controls work; the default hull collision radius remains unchanged. Review captures are in `references/`. The final browser console check showed no new errors after fixing preview reporting; an older captured console error belonged to the corrected preview-only message handler. Free-flight heading alignment is covered by geometry tests; a live overworld flight and a performance benchmark were not performed.
